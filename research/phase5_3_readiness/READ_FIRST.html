Development flow

Three jobs on the receiving Mac

  1. Source: observe current main and PR92/93 state and optionally copy both exact public source revisions into separate checkouts.
  2. Data: locate known completed aggregate summaries and verify the reviewed local fluorescence-image inventory. Missing original-Mac inputs remain explicit blockers.
  3. Model: capture author source, model metadata and configuration text at observed revisions. No weights or downloaded model code are executed.

The jobs run concurrently on three worker threads. tracker.json updates as they finish; REPORT.html summarizes the final states. A completed preflight job is not a completed biological experiment.

What improved in this package?

  • A source-bounded batch-usage register now distinguishes added plates from genuinely different registered batches.
  • A tested five-channel inventory verifier checks bytes, TIFF signatures and complete channel groups; it deliberately leaves pixel quality and registration unverified.
  • A parallel runner records completion, partial evidence and blockers independently.
  • The model-source review identifies grouped-channel inputs, patch-token versus image-vector output, and the need to isolate the authors’ older software environment.
  • A separate source-only publisher can preserve the reviewed readiness code and documents in a new draft PR based on PR93’s branch.

Verify SHA256SUMS, run the supplied synthetic tests, then launch the preflight with a new output directory. After source capture, the optional publication step in LOCAL_RUNBOOK.md verifies the source whitelist and creates a new draft PR. Existing PR92/93 remain unchanged. This handoff’s new code is not claimed to have been pushed until that helper prints a verified URL and SHA.

Decisions before a model experiment

  • Identify one matched image cohort with trustworthy guide/gene identities and experimental units.
  • Resolve intensity processing, channel mapping, pooling and field-to-well aggregation.
  • Check model training overlap and checkpoint licensing; use a separate runtime for compatibility work.
  • Freeze a full-channel versus reduced-channel comparison with a matched CellProfiler reference. Evaluate language alignment separately.

ChAda-ViT uses DINO-style self-supervised learning; it is not specifically an extension of DINOv2. The architecture remains proposed for Perturb-LM.
